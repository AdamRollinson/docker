Clone the repository and build from the `alpine` directory.

```bash
git clone https://github.com/AdamRollinson/docker.git
cd docker/alpine
./build.sh
```

This builds every image in order: `base`, then `php`, `php-slim`, `php-nginx`, `php-nginx-dev`, `php-fpm` and `php-dev` for each PHP minor in `php-versions.txt`. Images are tagged locally with both the minor and the exact release, exactly as CI publishes them. PHP is compiled from source, so the first build of each minor takes several minutes; later builds reuse the layer cache.

## Build a single image

Build arguments for the php image: `PHP_VERSION` is the minor without the dot (used for the `php84` and `php-fpm84` compatibility names) and `PHP_PATCH_VERSION` is the release to compile, which is required. `PHP_SOURCE_SHA256` and `PHP_SOURCE_URL` take the other two columns of `php-versions.txt`; the URL defaults to `www.php.net/distributions`, which only has final releases, and the GPG signature is checked either way.

```bash
# Base
docker build -t rollogi/base:latest ./alpine/base

# PHP 8.4
docker build \
  --build-arg PHP_VERSION=84 \
  --build-arg PHP_PATCH_VERSION=8.4.27 \
  --build-arg PHP_SOURCE_SHA256=dcf93923b0e38e0d5252b25b796520b5a47761a08b3488b6d0b5d1115764d3f0 \
  -t rollogi/php:8.4 \
  ./alpine/php

# PHP-Nginx 8.4 (php-fpm comes from the php image, compiled from the same source)
docker build \
  --build-arg PHP_IMAGE_TAG=8.4 \
  --build-arg PHP_VERSION=84 \
  -t rollogi/php-nginx:8.4 \
  ./alpine/php-nginx

# PHP-Nginx-Dev 8.4
docker build \
  --build-arg PHP_IMAGE_TAG=8.4 \
  --build-arg PHP_VERSION=84 \
  -t rollogi/php-nginx-dev:8.4 \
  ./alpine/php-nginx-dev

# PHP-Dev 8.4 (the CLI with Xdebug and PCOV, on the php image)
docker build \
  --build-arg PHP_IMAGE_TAG=8.4 \
  --build-arg PHP_VERSION=84 \
  -t rollogi/php-dev:8.4 \
  ./alpine/php-dev
```

## Extra extensions

```bash
PHP_EXTRA_EXTENSIONS="ldap memcached mongodb" ./alpine/build.sh
```

Bundled extensions are compiled from the PHP source, anything else from the latest stable PECL release, and an extension that cannot be built fails the build. Set `PHP_EXTRA_BUILD_DEPS` for `-dev` packages the build does not already know. See [the php image](/images/php#adding-extensions).

## Multi-architecture builds

CI builds `linux/amd64` and `linux/arm64` natively, each on its own runner. Locally, buildx can build both, emulating the other architecture with QEMU (expect a slow compile):

```bash
docker buildx create --name multi --driver docker-container --use
docker buildx build --platform linux/amd64,linux/arm64 \
  --build-arg PHP_VERSION=84 --build-arg PHP_PATCH_VERSION=8.4.27 \
  -t rollogi/php:8.4 ./alpine/php
```

## Checking the pins

```bash
alpine/check-php-versions.sh            # report pinned vs php.net, and pinned vs latest PECL
alpine/check-php-versions.sh --update   # rewrite the pins (release, checksum, URL) and PECL patch releases
```

This is the same script the scheduled bump job runs. See [Automatic updates](/releases/automatic-updates).

## Requirements

- Docker with BuildKit (any current Docker Desktop or Engine).
- Network access to `dl-cdn.alpinelinux.org`, `www.php.net`, `downloads.php.net` (pre-releases), `pecl.php.net`, `getcomposer.org` and Docker Hub.
- A wrong `PHP_PATCH_VERSION`, checksum or URL fails fast at the download or verification step, which is intentional.
