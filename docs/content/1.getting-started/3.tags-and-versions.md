## Two tags per image

Every image is published under two tags for each supported PHP minor.

| Tag | Example | Behaviour |
|-----|---------|-----------|
| Minor | `rollogi/php:8.4` | Moves forward to the newest pinned final release of that minor. Never a pre-release. |
| Exact release | `rollogi/php:8.4.27` | Immutable. Never republished with a different PHP build. |
| Pre-release channel | `rollogi/php:8.6-rc` | Moves with each release candidate of a minor that has no final release yet. |

Use the minor tag where you want PHP security fixes to arrive on their own. Pin the exact tag in production if you want to control exactly when PHP changes, then move it deliberately.

The same scheme applies to `php-slim`, `php-nginx`, `php-nginx-dev`, `php-fpm` and `php-dev`. The `base` image has a single `latest` tag.

### Pre-release channel

A minor whose pin is a release candidate, beta or alpha is published on a channel tag instead of the bare minor. PHP 8.6 is currently `php:8.6-rc` plus the exact tag in Alpine's spelling, `php:8.6.0_rc4` (php.net spells it `8.6.0RC4`). There is no `php:8.6` tag yet, so a deployment tracking a minor tag can never pick up a candidate by accident.

The channel is derived from the pin itself: `8.6.0_rc4` gives `8.6-rc`, a `_beta2` pin would give `8.6-beta`. When php.net releases 8.6.0 the automatic bump pins it, that build publishes `php:8.6` and `php:8.6.0`, and `php:8.6-rc` simply stops moving.

::warning
Treat the channel as experimental until the final release. The `imagick` extension does not support 8.6 yet and is left out, and Xdebug in the dev image is an alpha from xdebug.org.
::

## How a release is pinned

The exact release for each minor lives in a single file in the repository, `alpine/php-versions.txt`:

```text [alpine/php-versions.txt]
8.4 8.4.27 dcf93923b0e38e0d5252b25b796520b5a47761a08b3488b6d0b5d1115764d3f0 https://www.php.net/distributions/php-8.4.27.tar.xz
8.6 8.6.0_rc4 93f208da9ae059bf6863b0e1d101e6c6475a7b0f0acbf6c084950ab522f514d8 https://downloads.php.net/~mbeccati/php-8.6.0RC4.tar.xz
```

Each line is `<minor> <release> <sha256> <tarball URL>`. Final releases come from `www.php.net/distributions`; pre-releases come from the release manager's directory on `downloads.php.net`. The build downloads the tarball, checks it against the checksum and against the signing keys of the php.net release managers (kept in the repository as `alpine/php/php-keyring.asc`), and compiles the CLI and php-fpm from it. After installation it asserts that `php -v` reports the pinned version. A tag therefore cannot contain a different PHP than its name says, and every extension is built against that exact source.

The PECL extensions (igbinary, msgpack, APCu, Redis, Imagick, and Xdebug for the dev image) are pinned the same way, with a version and checksum per minor, in `alpine/php/pecl-extensions.txt`.

## How updates arrive

PHP is compiled from php.net's own tarballs, so there is no distribution packaging delay. A scheduled job runs every four hours and:

1. Reads php.net's releases feed for each minor, or its pre-release feed for a minor without a final release yet.
2. Compares each pin with the newest release, and rewrites the line (release, checksum, URL) when php.net has a newer one. Patch releases of the pinned PECL extensions are applied the same way.
3. Commits the new pin to `main` and dispatches the build, which publishes the new exact tag and moves the minor tag.

```text
PHP 8.4: pinned 8.4.26, php.net 8.4.27 (security release), update available
```

From the moment php.net publishes a release, the worst case to a published image is roughly four hours plus the build.

::tip
Images are also rebuilt weekly even when nothing changed, so Alpine's own security fixes for musl, OpenSSL, Nginx and friends ship without waiting for a PHP release.
::

## Checking what a tag contains

```bash
docker run --rm rollogi/php:8.4 php -v
docker inspect rollogi/php:8.4 --format '{{ index .Config.Labels "org.opencontainers.image.version" }}'
```

The `org.opencontainers.image.version` label carries the exact PHP release, and every image ships with an SBOM and provenance attestation you can inspect with `docker buildx imagetools inspect`.
