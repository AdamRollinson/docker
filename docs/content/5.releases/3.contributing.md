## Repository layout

| Path | Purpose |
|------|---------|
| `alpine/build.sh` | Builds all images locally in dependency order. |
| `alpine/php-versions.txt` | Pinned PHP release per supported minor. The single source of truth. |
| `alpine/check-php-versions.sh` | Compares pins with the Alpine repositories and php.net; `--update` rewrites the file. |
| `alpine/test.sh` | Smoke tests; CI runs them against every candidate, `test.sh all 8.4` runs them locally. |
| `alpine/release-notes.sh` | Renders the GitHub release notes for a published PHP release from the Docker Hub digests. |
| `alpine/notify.sh` | Posts a JSON message to `NOTIFY_WEBHOOK_URL`; no-op without it. |
| `alpine/base/` | Base image: Dockerfile, `entrypoint-lib.sh`, `run-service`, `container-logs`. |
| `alpine/php/` | PHP image: Dockerfile, `php.ini.template`, `php-entrypoint.sh`. |
| `alpine/php-nginx/` | Web image: Dockerfile, Nginx templates, `www.conf.template`, entrypoint, `healthcheck.sh`. |
| `alpine/php-nginx-dev/` | Dev image: Dockerfile, Xdebug and no-cache templates, entrypoint. |
| `.github/workflows/docker-build.yml` | Build, scan and publish pipeline. |
| `.github/workflows/php-version-bump.yml` | Four-hourly PHP pin bump. |
| `.vex/openvex.json` | VEX statements attached to every image. |
| `ENV.md`, `SECURITY.md`, `CLAUDE.md` | Variable reference, CVE notes, and repository conventions. |
| `docs/` | This documentation site. |

## Adding a PHP version

1. Confirm Alpine edge has the packages: `docker run --rm alpine:3.24 apk search -x --repository=https://dl-cdn.alpinelinux.org/alpine/edge/community --repository=https://dl-cdn.alpinelinux.org/alpine/edge/testing php87`.
2. Add a line to `alpine/php-versions.txt`, for example `8.7 8.7.0`.
3. Build it locally: `./alpine/build.sh` or the single-image commands on [Building locally](/getting-started/building-locally).
4. Update the supported versions in `README.md`, `CLAUDE.md` and the [Introduction](/getting-started) page.

Everything else, from the CI matrix to the bump job, reads the file.

## Adding a configuration variable

1. Add the `ENV` default to the relevant Dockerfile.
2. Reference it in the template (`php.ini.template`, `www.conf.template` or an Nginx template) or handle it in the entrypoint.
3. Document it in `ENV.md`, `README.md` and the [environment variable reference](/configuration/environment-variables).

If the setting is already expressible as `php.<setting>` or `fpm.pool.<setting>`, consider whether it needs a named variable at all.

## Conventions

- Commit messages are short, plain, one-line summaries with no type prefixes.
- Every image must keep zero setuid binaries, zero Trivy CRITICAL or HIGH findings, and pass `alpine/test.sh`. Add a check there for any new behaviour you introduce.
- Pin everything that can be pinned: actions by SHA, the base by digest, PHP by release.
- Templates must not write into `/etc` at runtime; render into `/run`.

## Working on this documentation

The site is a Nuxt 4 application in `docs/`, built with Nuxt UI and Nuxt Content and deployed as static assets on Cloudflare Workers.

```bash
cd docs
pnpm install
pnpm dev          # http://localhost:3000
pnpm check        # lint and typecheck
pnpm generate     # static output in .output/public
```

Pages are Markdown files under `docs/content/`; folder and file prefixes control navigation order. Edit a page and the dev server reloads it. Cloudflare builds the `docs` directory on every push to `main` that touches it and can give each pull request a preview URL.
