`rollogi/php-slim:{version}` carries exactly the PHP that [php](/images/php) carries (the same compiled CLI and PHP-FPM binaries, the same extensions and the same `php.ini` settings) on plain Alpine, and very little else. It is built from the `slim` target of the php Dockerfile, so both images come from one compile of each release.

It is meant as the final stage of a production build: install dependencies in `rollogi/php`, then copy the application into `rollogi/php-slim`.

| | php | php-slim |
|---|---|---|
| PHP CLI and PHP-FPM, every extension | Yes | Yes |
| Compressed size (8.4, arm64) | 53.5 MB | 39 MB |
| bash, git, curl, nano, Composer | Yes | No |
| Headers, `phpize`, `php-ext-install` | Yes | No |
| `php.*`, `fpm.pool.*`, `fpm.global.*` overrides | Yes | Yes |
| `APP_INSTALL` | Yes | Yes, output untagged |
| Worker mode (`CLI_COMMAND`), cron, `SMTP_*` mail relay | Yes | No |
| `[service]` log tagging, `LOG_FORMAT=json`, `LOG_MODE=file` | Yes | No |

## Production build

```dockerfile [Dockerfile]
FROM rollogi/php:8.4 AS deps
WORKDIR /app
COPY composer.json composer.lock ./
RUN composer install --no-dev --no-scripts --prefer-dist --optimize-autoloader

FROM rollogi/php-slim:8.4
COPY --from=deps /app/vendor /app/vendor
COPY . /app
```

## Modes

The default command prints the PHP version, any other command is run as given, and `serve` runs PHP-FPM:

```bash
# A CLI command or worker (no restart loop: let the orchestrator restart the container)
docker run --rm rollogi/php-slim:8.4 php artisan queue:work --max-jobs=1000

# PHP-FPM on 0.0.0.0:9000 for a web server in another container
docker run -d --name app -v "$PWD":/var/www/html:ro rollogi/php-slim:8.4 serve
```

`serve` renders the pool from the same template and `PHP_FPM_*` variables as [php-fpm](/images/php-fpm), including `PHP_FPM_LISTEN_ALLOWED_CLIENTS`, and logs PHP-FPM to stderr. Keep port 9000 on a private network.

## Health check

There is no `HEALTHCHECK` in the image, because its default command is a CLI one. When it runs `serve`, use the bundled `php-fpm-healthcheck`, which sends the pool's ping path over FastCGI (written in PHP, so the image needs no `cgi-fcgi`):

```yaml [compose.yaml]
services:
  php:
    image: rollogi/php-slim:8.4
    command: serve
    healthcheck:
      test: ["CMD", "php-fpm-healthcheck"]
      interval: 30s
      timeout: 3s
```

It follows `PHP_FPM_LISTEN`, or takes an explicit `host:port` or socket path to check another PHP-FPM.

## Read-only root filesystem

Configuration is rendered into `/run/php` at start-up, so mount `/run` and `/tmp` as tmpfs. `mode=1777` lets any `--user` write there:

```bash
docker run --read-only --tmpfs /run:mode=1777 --tmpfs /tmp --user 4321:4321 rollogi/php-slim:8.4 serve
```

## What is inside

- PHP CLI (`/usr/local/bin/php`) and PHP-FPM (`/usr/local/sbin/php-fpm`), the shared extensions and their `conf.d` ini files
- The shared libraries those link against, recorded by the build stage, plus `tini` as PID 1
- `php.ini.template` and `www.conf.template`, rendered by a POSIX `sh` entrypoint with a small PHP helper instead of `envsubst`
- busybox, as in every Alpine image (its applets include `wget` and `nc`)
- The non-root `appuser` (UID and GID from `APP_UID`/`APP_GID`, default 1000), with `/app` as the working directory

To add an extension, build it in `rollogi/php` and copy the `.so` and its ini file across; the runtime libraries it needs must then be added with `apk` in the slim stage.
