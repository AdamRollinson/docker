`rollogi/php-dev:{version}` is the [php](/images/php) CLI image plus Xdebug, PCOV and development defaults. It is meant for running PHPUnit, Pest, PHPStan or Psalm locally and in CI. Both extensions are compiled against the php image's headers at the versions `pecl-extensions.txt` pins for the minor: Xdebug 3.5 for 8.2 to 8.5 and a 3.6 alpha from xdebug.org for 8.6, PCOV 1.0.12 for every minor. Everything on the [php](/images/php) page applies here too, including worker mode, cron, `APP_INSTALL` and `php.*` overrides.

::warning
This image displays errors and has no memory limit. Do not use it in production.
::

## What changes from php

| Change | Detail |
|--------|--------|
| Xdebug and PCOV installed | Xdebug is loaded when `PHP_DEBUGGER=xdebug` (the default), PCOV when `PHP_DEBUGGER=pcov`; never both, because both hook code coverage. |
| `PHP_DISPLAY_ERRORS=On`, `PHP_ERROR_REPORTING=E_ALL` | Every error is printed. |
| `PHP_MEMORY_LIMIT=-1` | No memory limit, so large test suites and static analysis run without tuning. |

## Quick start

```bash
# Tests with PCOV coverage, the fast driver
docker run --rm -v $(pwd):/app -e PHP_DEBUGGER=pcov \
  rollogi/php-dev:8.4 vendor/bin/phpunit --coverage-text

# Xdebug's coverage mode instead (slower, but adds path and branch coverage)
docker run --rm -v $(pwd):/app -e XDEBUG_MODE=coverage \
  rollogi/php-dev:8.4 vendor/bin/phpunit --coverage-text

# Step debugging a CLI command: the trigger starts a session with your IDE
docker run --rm -v $(pwd):/app -e XDEBUG_TRIGGER=1 \
  --add-host=host.docker.internal:host-gateway \
  rollogi/php-dev:8.4 php artisan app:import
```

The working directory is `/app`. With the default `XDEBUG_START_WITH_REQUEST=trigger`, a debugging session only starts when `XDEBUG_TRIGGER` or `XDEBUG_SESSION` is set, so plain commands run at full speed apart from Xdebug's `develop` mode. Set `PHP_DEBUGGER=none` to load neither extension.

## In CI

Run the image from a step with `docker run`, so its entrypoint renders php.ini and loads the chosen driver:

```yaml [.github/workflows/tests.yml]
jobs:
  tests:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v5
      - name: Tests with coverage
        run: |
          docker run --rm -v "$PWD:/app" -e PHP_DEBUGGER=pcov rollogi/php-dev:8.4 \
            sh -c 'composer install --no-progress && vendor/bin/phpunit --coverage-clover coverage.xml'
```

::note
A GitHub Actions job `container:` is started with the runner's own entrypoint, so this image's entrypoint never runs there: no php.ini is rendered and neither Xdebug nor PCOV is loaded. If you use `container:` anyway, load the driver per command, e.g. `php -d extension=pcov.so -d pcov.enabled=1 vendor/bin/phpunit --coverage-text`.
::

The image is published for `linux/amd64` and `linux/arm64`, so the same tag works on GitHub's arm64 runners.

## Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `PHP_DEBUGGER` | `xdebug` | `xdebug`, `pcov` or `none`. Any other value stops the container, as does `pcov` on PHP 8.6, where PCOV is not built yet (its 8.6 fixes are still unmerged upstream). |
| `PCOV_DIRECTORY` | *(empty)* | Directory PCOV collects coverage for. Empty lets PCOV detect `src`, `lib` or `app`. |
| `PCOV_EXCLUDE` | *(empty)* | Regex of paths PCOV skips. |
| `XDEBUG_MODE` | `develop,debug` | Any Xdebug modes: `debug`, `develop`, `coverage`, `profile`, `trace`, `gcstats`. |
| `XDEBUG_START_WITH_REQUEST` | `trigger` | `yes`, `no` or `trigger`. |
| `XDEBUG_CLIENT_HOST` | `host.docker.internal` | Where your IDE listens. On Linux add `--add-host=host.docker.internal:host-gateway`. |
| `XDEBUG_CLIENT_PORT` | `9003` | IDE port. |
| `XDEBUG_DISCOVER_CLIENT_HOST` | `false` | Derive the IDE host from the request instead. |
| `XDEBUG_IDEKEY` | `PHPSTORM` | IDE key. |
| `XDEBUG_OUTPUT_DIR` | `/tmp/xdebug` | Profiles and traces land here; mount it to keep them. |
| `XDEBUG_LOG_LEVEL` | `3` | Xdebug log verbosity. |

Any other Xdebug or PCOV setting can be passed as `php.xdebug.<setting>` or `php.pcov.<setting>` through the generic override mechanism.

## How it is wired

Xdebug and PCOV are built with `php-ext-install --no-enable --pinned`, so neither has an ini file in the image. At startup the php-dev entrypoint calls `render_debugger` (from `entrypoint-lib.sh`, shared with [php-nginx-dev](/images/php-nginx-dev)), which renders `/run/php/conf.d/50-xdebug.ini` or `50-pcov.ini` from the templates in `/usr/local/etc/php/debug/`. `PHP_INI_SCAN_DIR=:/run/php/conf.d` adds that directory to PHP's scan path, and the entrypoint then hands over to the regular php entrypoint. The rendered ini lives under `/run`, so the image works with `--read-only` and `--user` like the php image, as long as `/run` is a tmpfs the runtime user can write (`--tmpfs /run:uid=1000,gid=1000`, the same recipe as php-nginx). If it cannot write `/run/php/conf.d` the container stops with an error rather than starting without the debugger you asked for.
