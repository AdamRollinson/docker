`rollogi/php:{version}` is the CLI image: PHP, Composer and the extensions a modern framework needs, with no web server. Use it for queue workers, schedulers, one-off commands and CI. PHP is compiled from the pinned php.net tarball, after its checksum and release manager signature are checked, and every extension is built against that same source. The image also contains `php-fpm` from the same build, which `php-nginx` and `php-fpm` use.

## Tags

| Tag | Content |
|-----|---------|
| `8.2`, `8.3`, `8.4`, `8.5` | Latest pinned release of that minor. |
| `8.6-rc` | Current 8.6 release candidate (experimental). No `8.6` tag until the final release. |
| `8.4.27`, `8.6.0_rc4` and other exact releases | Immutable. |

See [Tags and versions](/getting-started/tags-and-versions).

## Extensions

apcu, bcmath, ctype, curl, dom, exif, fileinfo, gd, iconv, igbinary, intl, json, mbstring, msgpack, mysqli, opcache, pcntl, pdo, pdo_mysql, pdo_pgsql, pdo_sqlite, pgsql, phar, posix, readline, redis, session, simplexml, soap, sockets, sodium, sqlite3, tokenizer, xml, xmlreader, xmlwriter, zip, imagick

The MySQL, PostgreSQL and SQLite drivers, Redis, APCu and sodium are all included, which covers the database, cache and encryption needs of a typical Laravel or Symfony application without a custom build. `igbinary` and `msgpack` are compiled in, and Redis is built with both as its serialisers. APCu is enabled for PHP-FPM and off for the CLI unless you set `php.apc.enable_cli=1`.

Most extensions are compiled into the PHP binary. The rest are shared and loaded by ini files in the scan directory `/usr/local/etc/php/conf.d`:

- **opcache** is a shared `zend_extension` before 8.5 (`10-opcache.ini`) and built in from 8.5. Either way it is controlled by the `OPCACHE_*` variables.
- **igbinary, msgpack, apcu, redis and imagick** are PECL extensions (`20-<name>.ini`), pinned with a checksum per minor in `alpine/php/pecl-extensions.txt`. **imagick** is left out on PHP 8.6 until it supports that version, and on 8.6 igbinary, msgpack, apcu and redis are built from upstream commits that fix the 8.6 build, because their latest releases do not compile against it yet.

The Alpine-era command names still work: `php84`, `php-fpm84`, `/usr/bin/php` and `/usr/sbin/php-fpm` are symlinks to the binaries in `/usr/local`. `php.ini` is still rendered into `/run/php` at startup.

Composer 2 is installed from the official installer with signature verification.

### Adding extensions

The published images deliberately stop there. For LDAP, GMP, Memcached, MongoDB, AMQP, YAML or any other bundled or PECL extension, build a variant with the `PHP_EXTRA_EXTENSIONS` build argument:

```bash
docker build \
  --build-arg PHP_VERSION=84 --build-arg PHP_PATCH_VERSION=8.4.27 \
  --build-arg PHP_EXTRA_EXTENSIONS="ldap gmp memcached mongodb" \
  -t myorg/php:8.4 ./alpine/php
```

A name that is a bundled extension (`ext/<name>` in the PHP source) is compiled from that source, anything else from its latest stable PECL release. The build installs the `-dev` packages for common extensions (amqp, bz2, ffi, gettext, gmp, ldap, memcached, tidy, xsl, yaml); name others in `PHP_EXTRA_BUILD_DEPS`. Runtime libraries are detected from the compiled binaries. An extension that cannot be fetched or compiled fails the build, so a typo cannot produce a silently smaller image. The set is recorded in the `io.rollogi.php.extra-extensions` label. `php-nginx` and `php-nginx-dev` built on top of your variant inherit the extensions.

You can also compile an extension in your own Dockerfile. The image keeps `phpize`, the PHP headers and a `php-ext-install` helper (bundled extensions need the PHP source, so in a derived image it builds from PECL or an `https://` URL):

```dockerfile
FROM rollogi/php:8.4
USER root
RUN apk add --no-cache --virtual .build autoconf file g++ gcc make musl-dev linux-headers \
    && php-ext-install mongodb && apk del .build
USER appuser
```

`php-ext-install <name> [<version>|<url> [<sha256>]] [-- <configure options>]` writes `20-<name>.ini` to enable it unless you pass `--no-enable`.

## Running commands

The entrypoint renders php.ini from your environment, then runs your command.

```bash
docker run --rm rollogi/php:8.4 php -v
docker run --rm -v $(pwd):/app -w /app rollogi/php:8.4 composer install --no-dev
docker run --rm -v $(pwd):/app -w /app -e PHP_MEMORY_LIMIT=1G rollogi/php:8.4 php bin/console cache:warmup
```

The default command is `php -v`, so running the image with no command just prints the PHP version. In practice you pass a command, or set `CLI_COMMAND` to run a long-lived worker.

### Queue workers

Set `CLI_COMMAND` and the entrypoint keeps it running: whenever the command exits, whether it crashed or stopped after `--max-jobs`, it is started again after `CLI_RESTART_DELAY` seconds (default 2). `CLI_MAX_RESTARTS` (default 0, unlimited) turns a persistent crash loop into a container exit carrying the worker's status, so your orchestrator's restart policy and alerting take over. Output is tagged `[worker]`.

```yaml [compose.yaml]
services:
  worker:
    image: rollogi/php:8.4
    working_dir: /app
    volumes:
      - ./:/app
    environment:
      CLI_COMMAND: php artisan queue:work --max-jobs=500 --tries=3
      CLI_MAX_RESTARTS: "50"
```

Worker mode applies when the container starts with the image's default command or the explicit `worker` command. Any other command runs as given, so `docker run ... rollogi/php:8.4 php artisan migrate` still works with `CLI_COMMAND` set.

### Startup commands

`APP_INSTALL` is a one-off command the entrypoint runs before the main command, in `APP_INSTALL_DIR` (default `/app`; `/var/www/html` on php-nginx, where it runs before php-fpm and nginx start). Output is tagged `[install]`. If it exits non-zero the container stops with that status, so an orchestrator sees a failed start rather than a healthy container with half-installed code.

```yaml [compose.yaml]
services:
  web:
    image: rollogi/php-nginx:8.4
    volumes:
      - ./:/var/www/html
    environment:
      NGINX_PORT: 8080
      APP_INSTALL: composer install --no-dev --optimize-autoloader && php artisan migrate --force
```

### Composer

Composer ships configured for containers. `COMPOSER_HOME` and `COMPOSER_CACHE_DIR` live under `/tmp/composer`, so it runs under any `--user` and with a read-only root filesystem. It never prompts, skips the funding notice, has no memory limit and does not warn in root mode. In your own image, keep the package cache out of the layers and reuse it between builds:

```dockerfile
FROM rollogi/php:8.4
COPY --chown=appuser composer.json composer.lock ./
RUN --mount=type=cache,target=/tmp/composer/cache,uid=1000 \
    composer install --no-dev --no-scripts --optimize-autoloader
COPY --chown=appuser . .
```

### Scheduler container

Pass `cron` as the command to run the configured jobs as the only process:

```bash
docker run --rm -d \
  -e CRON_SCHEDULE="* * * * *" \
  -e CRON_COMMAND="php /app/artisan schedule:run" \
  -v $(pwd):/app \
  rollogi/php:8.4 cron
```

Jobs come from `CRON_SCHEDULE` plus `CRON_COMMAND`, from a crontab mounted at `/etc/crontabs/app` (`CRONTAB_FILE`), or both. Output is tagged `[cron]`, and an invalid crontab stops the container at startup with the parser's message.

## Configuration

PHP settings are environment variables. The named ones cover the common cases and any other setting can be passed as `php.<setting>`.

```bash
docker run --rm \
  -e PHP_MEMORY_LIMIT=512M \
  -e PHP_DATE_TIMEZONE=Europe/London \
  -e php.max_input_vars=5000 \
  rollogi/php:8.4 php -i | grep -E "memory_limit|date.timezone|max_input_vars"
```

The full list is on [PHP settings](/configuration/php-settings) and in the [environment variable reference](/configuration/environment-variables).

## How php.ini is loaded

The rendered php.ini is written to `/run/php/php.ini` and PHP finds it through the `PHPRC` environment variable. The stock `/etc/php8x/` tree stays root-owned and unmodified, so a compromised script cannot rewrite PHP's configuration. See [Users and permissions](/configuration/users-and-permissions).

## Layout

| Path | Purpose |
|------|---------|
| `/usr/local/etc/php/php.ini.template` | Template rendered at startup. |
| `/run/php/php.ini` | Rendered php.ini (`PHPRC=/run/php`). |
| `/etc/php8x/conf.d/` | Stock extension ini files, root-owned. |
| `/usr/bin/php` | Symlink to the versioned binary (`php84`). |
| `/usr/local/bin/composer` | Composer 2. |
| `/usr/local/bin/php-entrypoint.sh` | Entrypoint. |

## Labels

`org.opencontainers.image.version` holds the exact PHP release, so `docker inspect` tells you what you are running without starting the container.
