`rollogi/frankenphp:{version}` runs [FrankenPHP](https://frankenphp.dev): the Caddy web server with PHP embedded in the same process. There is no FastCGI hop and no separate PHP-FPM, Caddy handles HTTPS on its own, and worker mode keeps your application booted between requests, which suits Laravel Octane, Symfony Runtime and similar.

## Quick start

```bash
# Plain HTTP on port 80, serving /app/public
docker run --rm -d -p 8080:80 -v $(pwd):/app rollogi/frankenphp:8.4

# Worker mode: the script boots once, then handles requests in a frankenphp_handle_request() loop
docker run --rm -d -p 8080:80 -v $(pwd):/app \
  -e FRANKENPHP_WORKER=/app/public/index.php \
  rollogi/frankenphp:8.4

# Automatic HTTPS for a real host name; keep /data so certificates survive restarts
docker run --rm -d -p 80:80 -p 443:443 -p 443:443/udp \
  -v $(pwd):/app -v caddy-data:/data \
  -e SERVER_NAME=app.example.com \
  rollogi/frankenphp:8.4
```

## What you get

- **Its own PHP build.** FrankenPHP needs a thread-safe PHP built as a library (`libphp.so`), so this image does not build on [php](/images/php). It compiles the same pinned tarball with the same checksum and signature checks, the same extensions and the same PECL pins, with `--enable-zts --enable-embed` added. The `php` CLI and Composer are included and share that build.
- **FrankenPHP from a pinned release.** The release and the Go toolchain that compiles it are pinned in `alpine/frankenphp/frankenphp-version.txt` (the tarball by checksum, Go by version, verified against the Go checksum database) and bumped by the same scheduled job as PHP.
- **Two features left out.** File-change worker restarts (`nowatcher`) are a development convenience that needs an extra C library, and the Mercure hub (`nomercure`) is AGPL licensed, so neither is compiled in.
- **The same conventions as the other images.** Non-root by default, `php.*` overrides, `APP_INSTALL`, cron, mail, tagged logs and a read-only root filesystem all work as they do in [php-nginx](/images/php-nginx).
- **The same request hygiene.** `/health` answers `OK` without running PHP, hidden files other than `/.well-known/` return 403, the usual security headers are set, and `Server` and `X-Powered-By` are removed.

## Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `SERVER_NAME` | `:80` | Caddy site address. A bare port serves plain HTTP; a host name turns on automatic HTTPS on 80 and 443 |
| `SERVER_ROOT` | `/app/public` | Document root |
| `FRANKENPHP_WORKER` | *(empty)* | Worker script kept in memory between requests; empty is classic mode |
| `FRANKENPHP_WORKER_NUM` | *(automatic)* | Worker threads for that script |
| `FRANKENPHP_NUM_THREADS` | *(automatic)* | Total PHP threads |
| `FRANKENPHP_CONFIG` | *(empty)* | Extra lines for the global `frankenphp` block |
| `CADDY_GLOBAL_OPTIONS` | *(empty)* | Extra Caddy global options, such as `email you@example.com` |
| `CADDY_EXTRA_CONFIG` | *(empty)* | Extra top-level Caddyfile config |
| `CADDY_SERVER_EXTRA_DIRECTIVES` | *(empty)* | Extra directives inside the site block, before `php_server` |

`PHP_SESSION_COOKIE_SECURE` defaults to `On` when `SERVER_NAME` is a host name (Caddy terminates TLS) and `Off` for a bare port or an `http://` address. Mount more site blocks as `/etc/frankenphp/Caddyfile.d/*.caddyfile`.

## Users and read-only root

The image runs as `appuser` and binds port 80 without extra capabilities (Docker lets unprivileged processes use low ports inside a container). It also runs under any `--user uid:gid`. For a read-only root filesystem, give it the same tmpfs mounts as the other images plus Caddy's two state directories:

```bash
docker run --read-only \
  --tmpfs /run --tmpfs /tmp --tmpfs /var/log --tmpfs /data --tmpfs /config \
  --cap-drop ALL --security-opt no-new-privileges \
  -v $(pwd):/app:ro rollogi/frankenphp:8.4
```

Use a volume rather than a tmpfs for `/data` when Caddy manages certificates.

## Logs and health

Caddy's own log goes through the same `LOG_MODE` and `LOG_FORMAT` switches: console lines tagged `[frankenphp]`, Caddy's JSON objects as they are with `LOG_FORMAT=json`, or `/var/log/frankenphp/caddy.log` with `LOG_MODE=file`. The Docker healthcheck asks Caddy's admin endpoint on `localhost:2019`, which works the same with or without HTTPS and is never published.

## Running other commands

`serve` (the default) starts FrankenPHP, plus supercronic when cron jobs are configured. Any other command runs as is, for example `docker run --rm rollogi/frankenphp:8.4 php artisan migrate` or `frankenphp php-cli script.php`.
